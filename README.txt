==========================================
■データ管理
==========================================


蚊データは、
性能と個性を分離して管理する。


------------------------------------------


colorType：


蚊の性能を管理する。


管理内容：

・色

・速度

・出現率

・セリフ文字色



現在：

constant.js管理。



対象：

BLACK

RED



------------------------------------------


attributeType：


蚊の人格を管理する。


管理内容：

・属性名

・出現率

・回避率



現在：

CSVによる外部管理。



管理ファイル：

data/attribute.csv



理由：

Excel編集、

追加、

バランス調整

を容易にするため。



------------------------------------------


dialogue：


属性ごとのセリフ管理。



管理内容：

・ID

・出現セリフ

・回避セリフ

・撃破セリフ

・吸血直前セリフ

・吸血完了セリフ



管理ファイル：

data/dialogue.csv

■UI管理
==========================================


ゲーム中のみ表示：


・スコア表示

・かゆみ耐性表示



タイトル画面では非表示。

・ゲームタイトル

・難易度表示

・タイトルセリフ表示

・スタートボタン



関連処理：

game.js

title.js



==========================================
■CSS構成
==========================================


UI・演出管理を分離するため、
CSSを分割管理している。



style.css：


基本画面、

タイトル画面、

共通設定。



gameParts.css：


ゲームパーツ用CSS。



effect.css：


演出用CSS。



目的：

UI追加や演出追加時の
管理性向上。

==========================================
■開発方針
==========================================


まずゲームとして成立することを優先する。


優先順位：


1. 基本システム

2. 操作感調整

3. 演出強化

4. コンテンツ追加



設定資料の追加より、
まずゲームとして成立する処理を優先する。



ただし断末蚊の個性要素である、


・属性

・セリフ

・蚊ごとのキャラクター性


については、
初期段階から拡張可能な構造を維持する。



------------------------------------------


設計方針：


性能データと個性データを分離する。



colorType：


蚊の性能。



例：

BLACK

RED



attributeType：


蚊の人格。



例：

rookie

chunibyo



dialogue：


セリフ管理。



現在：


attribute.csv

dialogue.csv


による外部データ管理。



将来的に、


属性

↓

セリフ

↓

特殊行動


という拡張を可能にする。
